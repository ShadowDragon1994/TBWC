# 淘宝文创工具使用说明

## 1. 功能范围

本项目复用 TradeMind 的管理端、PostgreSQL、Redis、Playwright 采集器、商品草稿、图片任务与刊登任务，并增加淘宝/天猫销售平台、淘宝 TOP 刊登 Provider 和 1688 供货店铺入口。

- 1688：供货来源登记与商品采集。
- 淘宝/天猫：目标销售平台，承接审核后的商品刊登任务。
- 任务恢复：复用现有租约、幂等、失败记录、重试与人工审核链路。

## 2. 安装

环境需要 Git、PowerShell 7、Go、Node.js/Corepack、PostgreSQL 和 Redis；也可使用 TradeMind Docker Compose。

```powershell
Copy-Item .env.example .env
./scripts/bootstrap-trademind.ps1
```

脚本下载 `vendor/trademind.lock.json` 锁定的 TradeMind 版本，并自动应用：

```text
patches/trademind-taobao.patch
```

生成的业务代码位于 `vendor/trademind-ai`。

## 3. 启动

```powershell
Set-Location vendor/trademind-ai
corepack pnpm install
corepack pnpm dev
```

| 服务 | 默认地址 |
|---|---|
| 管理端 | `http://127.0.0.1:8000` |
| 后端 API | `http://127.0.0.1:8081` |
| 采集器 | `http://127.0.0.1:3100` |
| PostgreSQL | `127.0.0.1:5432` |
| Redis | `127.0.0.1:6379` |

系统 pnpm 版本不匹配时，统一使用 `corepack pnpm`。

## 4. 创建淘宝店铺

1. 登录管理端。
2. 打开“设置 → 平台接入设置 → 淘宝开放平台”。
3. 填写淘宝开放平台 `App Key`、`App Secret`；自定义网关或沙箱按需填写。
4. 打开“店铺管理 → 新建店铺”。
5. 销售平台选择“淘宝 / 天猫开放平台（taobao）”。
6. 保存后进入“店铺授权”，填写店铺 Session/Access Token。
7. 点击“测试连接”，系统通过 TOP 卖家信息接口校验授权。

凭据只填写在设置或店铺授权页面，不写入代码、文档、日志或 Git。

## 5. 登记和采集 1688 商品

1. 在“店铺管理 → 新建店铺”选择“1688 供货店铺（1688）”。
2. 填写店铺名称，可选填写供应商/会员 ID。
3. 进入“采集 → 采集任务”，平台选择 1688。
4. 首次采集需要登录时，点击“打开 1688 登录浏览器”。
5. 完成人工登录或安全验证后重新提交采集任务。
6. 采集结果进入本地商品草稿库，人工剔除或保留。

## 6. 采集淘宝/天猫商品

1. 进入“采集 → 采集任务”。
2. 选择“淘宝/天猫采集器”。
3. 填写标准商品详情页链接并提交。
4. 出现登录或安全验证提示时，打开淘宝/天猫采集浏览器完成验证。
5. 在商品草稿库检查标题、价格、图片、参数和 SKU。

淘宝/天猫外链图片建议刊登前同步到项目对象存储，避免源链接失效。

## 7. 配置淘宝刊登

进入“设置 → 平台刊登设置 → 淘宝商品刊登配置”：

| 参数 | 说明 |
|---|---|
| 发布市场 | `taobao`、`tmall` 或 `litetao` |
| 默认类目 ID | 淘宝开放平台目标类目 ID |
| 默认 SPU ID | 天猫市场必填，淘宝可留空 |
| Biz Type | 与平台约定时填写 |
| Schema XML 模板 | 按目标类目发布规则生成的完整 Schema |

Schema 模板支持：

```text
{{title}}
{{description}}
{{main_image_url}}
{{price}}
{{stock}}
{{sku_code}}
```

占位符在提交前执行 XML 转义。不同类目的字段规则不同，应先从淘宝开放平台取得对应 Schema，再校准模板。任务 options 可用 `category_id`、`spu_id`、`market` 或 `item_schema` 覆盖默认配置。

## 8. 图片处理与审核

1. 从商品草稿库选择保留商品。
2. 进入图片任务，选择已配置的图片 Provider 或 Photoshop API 流程。
3. 设置模板、输入图片和输出规格后提交异步任务。
4. 完成后检查主图、详情图、尺寸、文字和输出地址。
5. 人工确认后标记为待刊登。

图片与刊登任务分开保存。刊登失败后重试不会重复已经完成的图片处理。

## 9. 创建淘宝刊登任务

1. 打开商品草稿详情并完成刊登检查。
2. 选择已授权的淘宝店铺。
3. 确认标题、描述、类目、图片、SKU、价格、库存和 Schema。
4. 创建刊登任务并完成人工确认。
5. Worker 调用 `alibaba.item.publish.submit`。
6. 成功后保存淘宝商品 ID、商品链接、请求摘要和 publication 状态。

该提交接口不返回远端 SKU ID，系统不会用本地 SKU 编码冒充远端 ID；后续应通过商品详情同步绑定。

## 10. 恢复与排错

- 每个任务有稳定 ID 和幂等键。
- Worker 领取任务后保存租约并定期续期。
- 平台结果和成功步骤写入 PostgreSQL。
- 恢复从最后已验证状态继续，不重复已确认副作用。

| 现象 | 处理 |
|---|---|
| 店铺下拉没有淘宝/1688 | 确认补丁已应用并重启后端，浏览器按 `Ctrl+F5` |
| 后端 502/503 | 检查 8081、3100、PostgreSQL 和 Redis |
| 淘宝连接失败 | 检查 App Key、App Secret、店铺 Session 和应用权限 |
| 缺少类目 | 配置 `default_category_id` 或任务 `category_id` |
| 天猫缺少 SPU | 配置 `default_spu_id` 或任务 `spu_id` |
| Schema XML 错误 | 检查对应类目的完整 Schema、XML 闭合和字段规则 |
| 采集要求登录 | 打开对应登录浏览器，完成登录/验证后重试 |

健康检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8081/health
Invoke-RestMethod http://127.0.0.1:3100/health
Invoke-WebRequest http://127.0.0.1:8000 -UseBasicParsing
```

## 11. 验证、升级与回滚

```powershell
Set-Location vendor/trademind-ai/backend
go test ./internal/providers/platform/taobao ./internal/providers/platform ./internal/modules/shop ./internal/api ./cmd/server
go vet ./internal/providers/platform/taobao
```

升级 TradeMind 时，更新锁文件后先执行：

```powershell
git -C vendor/trademind-ai apply --check ../../patches/trademind-taobao.patch
```

代码级回滚：

```powershell
git -C vendor/trademind-ai apply -R ../../patches/trademind-taobao.patch
```

业务任务的撤销通过任务状态、人工下架或平台后台处理，保留数据库审计记录。
