# 发布任务看板实施方案

## 目标

为个人使用场景增加独立的发布任务工作流，优先支持小红书和抖音，并保证 Edge 浏览器中的交互可用。

## 数据设计

- 发布任务与商品、创作记录可关联，但保留商品名和标题快照，避免来源删除后任务不可读。
- 状态固定为：编辑中、待审核、可发布、已发布。
- 记录计划发布时间、备注、发布链接和实际发布时间。
- 未发布且超过计划时间的任务显示逾期。
- 标记为已发布时必须填写 HTTPS 发布链接。

## 页面设计

- 新增“发布任务”导航和四列看板。
- 支持平台、商品关键字筛选。
- 支持从创作记录快速带入商品、平台和标题，也允许手动建任务。
- 卡片提供状态推进、编辑、删除和打开发布链接操作。
- 使用原生按钮完成流转，确保 Edge 键盘与鼠标操作稳定。

## 实施顺序

1. 先写发布任务 API 失败测试。
2. 增加 SQLite 表、校验、仓储、服务和 API。
3. 增加前端 API、看板、任务表单和交互测试。
4. 接入本地备份恢复。
5. 运行完整自动化测试、构建和 Edge 实机回归。
6. 代码审查后提交并推送 GitHub 私有仓库。
