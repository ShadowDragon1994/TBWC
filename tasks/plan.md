# Windows 一键启动与自动备份实施方案

## 目标

让个人用户无需终端即可启动造物台，并在应用运行期间自动生成可恢复的完整备份。

## 设计决策

- 继续使用项目内已忽略的 `data/`，保留现有数据库、图片和 AI 密钥。
- 生产服务由 Express 同时提供 API、上传图片和 Vite 构建页面。
- 仅监听 `127.0.0.1`，避免局域网暴露个人数据。
- 自动备份写入 `data/backups/`，当天已成功备份则跳过。
- 启动时检查一次，之后每小时检查；默认保留最近 30 份。
- 使用 `启动造物台.cmd` 调用 PowerShell：构建、隐藏启动、等待 `/ready`、用 Edge 打开。
- 日志和进程信息写入已忽略的 `tmp/`。

## 实施切片

1. 测试并实现生产静态页面托管。
2. 测试并实现自动备份命名、跳过和保留策略。
3. 接入生产启动入口和 npm 脚本。
4. 制作 Windows 双击启动脚本。
5. 验证生产构建、自动备份、Edge 打开及备份 ZIP 内容。
6. 代码审查、提交并推送。

## 安全边界

- 不删除数据库、上传图片或 AI 密钥。
- 只清理符合造物台备份命名规则的旧 ZIP。
- 使用临时文件写入成功后再原子重命名，避免留下损坏备份。
- 启动脚本不输出或复制 AI 密钥。
